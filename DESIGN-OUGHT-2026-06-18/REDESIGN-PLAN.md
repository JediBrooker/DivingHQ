# DivingHQ Meet-Day Redesign — Stage-Rail Control Room

**A phased, flag-gated rollout that makes the meet-day operator's screen a function of one focused stage instead of nine simultaneous panels — without changing a single scoring rule.**

---

## North star

> The meet-day operator can answer **where-am-I / what-do-I-do-now / what's-stopping-me / how-do-I-undo** from one resting layout, because the screen is a function of one focused stage rather than nine simultaneous panels — and no scoring rule, trim/sync calculation, or socket data path changes to get there.

## Framing: why this is a REDESIGN, not a polish pass

The DESIGN-IS-2026-06-18 audit returned a **REDESIGN** verdict on a deliberately narrow basis. DivingHQ is useful and technically mature: scoring/trim/sync math, the `score_received` data path, and the offline outbox are unit-tested *below* the UI and behave correctly under load. The failure is not capability — it is **comprehensibility under pressure**. The meet-day Control Room (`src/views/ControlView.vue`, a confirmed **4261-line** single-file component) renders a three-column wall that displays every event lifecycle at once: a colour-cycling next-action button, a `readinessItems` strip, five independent overflow-menu systems, and 6+ always-present right-column panels. The operator must *decode* the screen — hover a tooltip, read a button's colour, remember which of fourteen modals holds the action — rather than *read* it.

That is the literal definition of the **Rams #4 (Understandable) = 1 (critical)** score the audit assigned, and it drags down five further principles judged at 1: **#3 aesthetic** (an accreted wall), **#5 unobtrusive** (~38 files carry animation, the resting live screen never stops moving), **#7 long-lasting** (the modal frame is copy-pasted into 7 component files plus 8 inline sites), **#9 environmental** (a live operator mounts Setup/Review/Super-Final markup it never uses), and **#10 as-little-design-as-possible** (nothing is subtracted).

The mandate, therefore: **preserve operating capability; remove visible decision load.** This plan re-lays-out state that already exists — it promotes the existing `workflowMode`/`orderWorkflowState` computeds from a buried strip to the top-level layout switch — and ships the riskiest change (re-laying-out the 4261-line live SFC) behind the same `VITE_*` build flag the team already trusts for the outbox, with the untouched original file as a one-line-revert. Foundation-first, monolith-last, flag-gated.

## The staged meet-day operating model

The chosen approach is **Stage-Rail** (winner of the scoreboard at 26.5; see appendix), with the strongest corrections grafted from the runner-up **Stage-Machine** and the **Command-First** approaches folded in.

**The operator never sees the whole meet at once.**

- **RAIL (left, persistent).** The meet timeline. Each event is a stage row carrying one honest **state token** (Setup / Ready / Live / Held / Review / Done) plus **at most one attention marker** (blocker | next-action | live). Selecting a row focuses the center. This is situational awareness and navigation — not action.
- **CENTER (one CURRENT STAGE panel).** Renders only the focused event, at full fidelity, in exactly one of four modes. **Mode is a consequence of stage state, not a user choice**: Upcoming → Setup, Live → Live, Completed → Review. **Recovery** is the one explicit cross-cutting mode, reachable from the header and *offered* (never seized) on a recovery signal.
- **DRAWER (right, closed by default).** Broadcast handoff, reserves, super-final seeding, audit feed, sponsor, manual entry — lazy-mounted on open, dismissed back to nothing.

The first live screen answers the **four questions positionally** from a never-moving layout:

| Question | Answered by | Fed by (existing) |
|---|---|---|
| **CURRENT STATE** | One resting stage header row: `StatusPill` + READY/DIVING/JUDGING + shot clock + connection badge, one row, no tooltips | `activeStatus` (`78-88`), `useShotClock`, `useMeetHold`, `socket.isConnected` |
| **NEXT ACTION** | One fixed, bottom-pinned primary-action slot that never moves | `nextBtnText`/`nextBtnTitle`/`nextBtnComplete`; `orderWorkflowState` in Setup, Next Diver → Finalise in Live |
| **BLOCKERS** | A compact plain-language blockers strip directly under the primary (disables it when non-empty; top blocker named with a Fix link) | `readinessItems` `{label,hint,onFix,severity}` (`1061-1169`) |
| **SAFE RECOVERY** | A deliberate Recovery lane consolidating hold/resume, score correction, withdraw-with-undo, reflow, offline/conflict/late-arrival trays — with the offline/conflict/late-arrival SIGNAL always visible above the switch (never lane-gated), the lane being where you *act* | `useMeetHold`, `openCorrection`, `withdrawRosterRow`, `reflowOpen`, the outbox trays |

**Modal consolidation** rests on three primitives + a placement rule: sequence-of-setup → `StageStep` (in-panel); discrete consequence-bearing task → `TaskSheet` (one a11y-correct `BaseModal`); ambient secondary → `DrawerPanel`.

The whole Control Room ships as **`ControlViewV2`** behind a build/route flag while the untouched `ControlView.vue` stays mounted as the rollback.

### Grafted corrections (the parts the winner got wrong, fixed inline)

- From **Stage-Machine**: referee verdicts (`failed`/`cap`/`redive`), the partial-score confirm, and the `signalingJudges` interrupt stay **on-canvas in Live mode** — collapsing the long tail into the drawer must never hide an action an operator needs in seconds.
- From **Command-First**: a late-entry/correction path also exists **within Live** so operators never feel trapped by the stage; Recovery is the consolidated home, not the only door.
- The auto-surfacing risk in the winner's own write-up is corrected to **offer-not-seize**, with SIGNAL split from RESOLUTION: an unresolved offline/conflict/late-arrival state always shows a **persistent, non-dismissible indicator above the mode switch in every mode** (the awareness the self-rendering trays carry today), while the *resolution* trays live in the Recovery lane. Recovery itself surfaces as a non-modal banner the operator enters deliberately — never a forced focus switch mid-score — and the always-on signal never depends on the operator already being in Recovery.

## Appendix — approaches considered

Four operating models were scored against four lenses (understandability, feasibility, migration-risk, completeness):

| Approach | Total | Why it ranked where it did |
|---|---|---|
| **Stage-Rail (winner)** | **26.5** | A persistent rail (situational awareness) + one mode-switched center (one thing to do now) + a closed drawer (everything else). Best understandability (7.5) and completeness (7) — every role gets its lane, not all lanes at once — and it promotes computeds that already exist. Migration-risk (5) is the cost of re-laying-out a 4261-line SFC, bounded by the flag + parallel file. |
| **Stage-Machine** | 26 | One NOW header + one next-required-action + a blockers strip + a recovery menu. Highest feasibility (8) because it touches the least, but lower completeness (6): without the rail, multi-event situational awareness is weaker. **Its insistence that referee verdicts and the partial-score path stay on-canvas was grafted into the winner (P6).** |
| **Command-First (Calm Canvas + Command Bar)** | 25 | A quiet canvas driven by a `⌘K` command bar. Lowest migration-risk among the action models (6) but a command bar alone does not answer "where am I" positionally for an operator under pressure. **Its "never trap the operator in a mode — a late-entry/correction path must exist in Live" correction was grafted into the winner (P6/P7).** |
| **Lane-Tabs (Setup/Run/Recover/Broadcast)** | 23.5 | Four top-level lanes as tabs. Strong completeness (7) but the worst migration-risk (3): tabs force a route/instance split, which collides head-on with the single-socket-subscription invariant (a dead instance receiving `score_received` could advance a live meet). Rejected on exactly that hazard, which the winner avoids by mode-switching the body of one mounted SFC. |

The winner was chosen because it raises the critical **#4 Understandable** score *structurally* — content is a function of one focused stage — while keeping the riskiest change behind a proven flag with the original file as a one-line-revert, and because its two acknowledged weaknesses (on-canvas correction paths, offer-not-seize Recovery) are cheaply corrected by grafting the runner-ups' best ideas rather than adopting their whole model.
